
# API Testing Project - Sprint_7

## Описание

Этот проект предназначен для тестирования API, включая функциональность работы с курьерами и заказами. Мы используем **pytest** для выполнения тестов, а **Allure** для создания отчетов.

## Структура проекта

```
/Sprint_7
│
├── /api/                # Клиент для взаимодействия с API
│   ├── __init__.py
│   ├── client.py        # Основной клиент для отправки запросов
│   └── routes.py        # Определения маршрутов API
│
├── /tests/              # Тесты, разделённые по категориям
│   ├── __init__.py
│   ├── test_courier.py  # Тесты для функциональности курьера
│   └── test_order.py    # Тесты для функциональности заказов
│
├── /utils/              # Вспомогательные утилиты
│   ├── __init__.py
│   ├── helpers.py       # Функции для генерации тестовых данных
│   └── assertions.py    # Классы и функции для проверок в тестах
│
├── requirements.txt     # Список зависимостей проекта
├── pytest.ini           # Конфигурация для pytest
└── conftest.py          # Общие настройки и фикстуры для тестов
```

## Установка зависимостей

Для установки всех зависимостей проекта используйте команду:

```bash
pip install -r requirements.txt
```

## Запуск тестов

### 1. Запуск тестов с использованием `pytest`:

Чтобы запустить тесты с использованием `pytest`, выполните команду:

```bash
pytest --alluredir=allure-results
```

Эта команда выполнит все тесты и сохранит результаты в папке `allure-results`.

### 2. Просмотр отчета Allure:

После выполнения тестов с использованием `pytest`, чтобы увидеть отчет в браузере, выполните команду:

```bash
allure serve allure-results
```

Это откроет отчет в браузере по умолчанию, где можно будет увидеть подробные результаты выполнения тестов.

## Описание тестов

### 1. **Тесты для курьеров (`test_courier.py`)**

- **`test_create_courier_success`**: Проверяет успешную регистрацию нового курьера.
- **`test_create_duplicate_courier`**: Проверяет, что нельзя создать двух одинаковых курьеров.
- **`test_create_courier_missing_fields`**: Проверяет, что запрос без обязательных полей (логин, пароль) возвращает ошибку.
- **`test_login_courier_success`**: Проверяет, что курьер может успешно авторизоваться.
- **`test_login_courier_invalid_credentials`**: Проверяет, что система вернет ошибку при неверном логине или пароле.
- **`test_delete_courier_nonexistent_id`**: Проверяет, что попытка удалить несуществующего курьера возвращает ошибку.
- **`test_delete_courier_success`**: Проверяет успешное удаление курьера.

### 2. **Тесты для заказов (`test_order.py`)**

- **`test_create_order_success`**: Проверяет успешное создание заказа.
- **`test_create_order_with_colors`**: Проверяет, что можно указать один из цветов, оба цвета или не указывать цвет.
- **`test_get_orders_success`**: Проверяет, что в ответе возвращается список заказов.
- **`test_create_order_missing_fields`**: Проверяет, что запрос без обязательных полей возвращает ошибку.
- **`test_accept_order_success`**: Проверяет успешное принятие заказа курьером.
- **`test_accept_order_invalid_courier_id`**: Проверяет, что запрос с неверным ID курьера возвращает ошибку.
- **`test_accept_order_invalid_order_id`**: Проверяет, что запрос с неверным ID заказа возвращает ошибку.
- **`test_get_order_missing_id`**: Проверяет, что запрос без номера заказа возвращает ошибку.
- **`test_get_order_nonexistent_id`**: Проверяет, что запрос с несуществующим номером заказа возвращает ошибку.

## Формат отчетов

Отчеты в **Allure** отображают:
- Статус тестов (успешно/неудачно).
- Подробности об ошибках для каждого шага.
- Структуру тестов по **Epic** и **Feature**.

### Пример отчета Allure:
- **Epic**: API Testing
- **Feature**: Courier Management, Order Management
- **Test steps**: Для каждого теста будут отображаться шаги, которые были выполнены, с указанием статуса.
